01 / RISK 情報漏洩とは何か 個人情報・営業秘密・技術情報が、権限のない相手に渡ること 主な流出経路 外部からの攻撃 フィッシング、不正アクセス、脆弱性の悪用、 ランサムウェア攻撃に伴うデータの窃取。 内部の人的要因 メールの誤送信、端末の紛失、情報の不正な持ち出し、 過剰なアクセス権限や管理の不備。 クラウド・生成AIの利用 クラウドの公開設定ミス、共有リンクの管理不備、 利用条件や社内ルールを確認せずに機密情報を入力する行為。 企業活動への影響 直接的な損失 調査・復旧費用、業務停止、顧客対応、損害賠償など。 中長期的な損失 顧客や取引先の信頼低下、契約の喪失、技術流出による競争力低下。 情報漏洩は、外部攻撃だけでなく日常の操作ミスからも起こる。 INFORMATION SECURITY 1/4 02 / DEFENSE 漏洩を防ぐ主要システム 認証・通信・端末・データ・監視を組み合わせる「多層防御」 DLP｜データ損失防止 機密情報を識別し、メール送信・外部媒体へのコピー・ クラウドへのアップロードなどを、設定に応じて検知・制限。 EDR / XDR｜脅威の検知と対応 EDRは端末の挙動を監視。XDRは端末・メール・IDなどの 情報を横断して分析し、調査や封じ込めを支援。 IAM / MFA｜ID・権限管理と多要素認証 IAMはIDとアクセス権限を管理。MFAは複数の認証要素を 用い、パスワード流出時の不正ログインを抑える。 SASE / ZTNA｜通信とアクセスの保護 SASEはネットワークとセキュリティ機能を統合。 ZTNAは利用者や端末を検証し、必要な資源への接続を制御。 SIEM / SOC｜ログ分析と監視運用 SIEMはログを集約・分析する仕組み。SOCは監視・分析・ 対応を担う組織や機能であり、両者は役割が異なる。 各機能の対象範囲や効果は、製品・設定・運用体制によって異なる。 INFORMATION SECURITY 2/4 03 / COMPANIES 主要企業と主な領域 代表的な関連企業を整理。掲載順は順位や市場シェアを示さない。 日本企業 デジタルアーツ Web・メールのフィルタリング、情報漏洩対策 トレンドマイクロ 端末・サーバーの保護、脅威の検知と対応 FFRIセキュリティ 脅威解析、国産の端末防御製品 ソリトンシステムズ 認証・アクセス制御、端末のセキュリティ対策 HENNGE クラウドサービスの認証・アクセス管理 海外企業 Palo Alto Networks ネットワーク保護、SASE、データ保護 CrowdStrike 端末防御、脅威の検知と対応、データ保護 Zscaler ゼロトラスト接続、クラウド型のデータ保護 Microsoft EntraによるID管理、Defenderによる脅威対策、 Purviewによるデータ保護・管理 INFORMATION SECURITY 3/4 04 / OPERATIONS 情報を守る運用の仕組み 製品の導入に加え、日常の管理と事故発生時の対応を整える 資産と情報の把握 端末・システム・保存先を把握し、情報の機密性に応じて分類。 誰が、どの情報へアクセスできるかを明確にする。 基本対策の継続 多要素認証、最小限の権限付与、更新プログラムの適用、 メールや共有設定の確認、従業員への継続的な教育。 生成AIの利用ルール 入力できる情報、利用可能なサービス、データの保存・学習利用 の条件を整理。監視や制御が及ぶ範囲も把握する。 検知と初動対応 不審な操作や通信を監視し、連絡先と担当者を明確化。 事故時は影響範囲を調査し、拡大防止と証拠の保全を進める。 復旧と再発防止 バックアップと復元手順を検証し、事業の復旧に備える。 事故の原因を分析し、権限・設定・運用ルールを見直す。 バックアップは復旧の備えであり、情報の流出そのものは防がない。 INFORMATION SECURITY 4/4
