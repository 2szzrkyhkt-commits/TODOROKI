# 過去記事の再活性化

Cloudflare の既存ビルドでサイトマップ同期後に記事を再集計する。canonical、公開日、構造化データ、広告には手を加えない。生成範囲は HTML コメント `article-revival` で識別でき、ソースと生成リンクを比較できる。元に戻す場合は変更コミットをリバートし、既存のビルドで再配信する。

- 下段は日本時間04:00に切り替わる。掲載候補は原則30日以上前の日付が確認できる基礎解説。日付欠損の一部は Git の公開履歴 `2fcc39948ba29cbdc088816bf1f592dcb9a9c1c0` を掲載時点の下限に使う。閾値は `tools/article-themes.mjs` で管理する。候補不足時は件数を縮める。
- 関連記事は同じ言語の本文リンク、テーマ、既存の手動リンクを照合する。時事記事は関連資料として扱うが下段の自動再紹介には回さない。新記事で日付が使えるように、公開時にホームの既存記事カタログまたは記事の構造化データに公開日を入れる。
- 既存のGA4人気枠は確定済みの集計期間を明示する。直近7日・30日の人気は各期間の実測データが揃った段階で更新する。過去記事のおすすめは日替わり表示で、人気順とは別の枠。
- 新着・過去テロップ、関連記事、テーマの読み順やおすすめ一覧は、既存の任意同意に従い `ticker_new_click`、`ticker_archive_click`、`related_article_click`、`recommended_article_click` を送信する。遷移先のパスは `article_path`。URLのクエリは送らない。

## 改善候補と下書き

`node tools/article-revival-report.mjs /path/to/private-input.json` で内部リンク候補、改善対象、X文案を生成する。入力なしでは記事構造だけを使い、検索指標とX文案は未取得として扱う。出力は運営者用。公開資産には含めない。

入力には Search Console のページ別集計 `current` と `previous` を指定できる。それぞれ `start`、`end`（YYYY-MM-DD、両端含む）、Search Analytics APIと同じ `rows`（`keys` はページURLのみ、`clicks`、`impressions`、`position`）を指定する。同じ長さの連続期間のみ差分比較する。任意の `indexing` はURL検査結果をサイト内パスで対応付けたオブジェクト。未取得を0と扱わない。

X文案は既存の投稿履歴から `posted`（`url` はサイト内パス、`date` は投稿日）を渡した場合だけ出す。確認済み解説を対象とし、同じ記事を90日以内に再提案しない。実際の投稿後は既存の履歴へ記録する。生成のみで、公開操作は手動。

## 効果測定

既存T06の点検を利用する。導入前、導入後7日、30日の同じ長さの期間を比較し、GA4は過去記事のページビュー、セッションあたりの表示、4イベントを確認する。GSCは過去記事のクリック・表示・CTR・平均順位を同じURL集合で照合する。URL検査は実測が取れたページだけ記録する。GA4とGSCのタイムゾーンはそれぞれの報告設定を使い、比較期間と欠測日を記録する。指標の変動をリリースの因果効果と断定しない。
