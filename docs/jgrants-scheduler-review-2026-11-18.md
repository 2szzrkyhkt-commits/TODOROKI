# T29 期限到来の検索語と保存途中のスナップショット

14:12 JSTの読取では「助成」875/922件を保存中、残る7語は11:15〜12:10 JSTに
再試行期限を過ぎているが未取得だった。旧処理はpendingの保存を常に先に返し、
大きな検索語の全保存が終わるまで別の取得を行わない。隔離テストでも
別の期限到来語を取得せずsavedとなる失敗を再現した。

同じ一周期で「取得1回」または「保存最大25件」のどちらか一つだけ実施する。
期限到来の取得を先に選ぶが、payloadが未保存途中の語は取得候補から除外する。
24時間以上保存中でも、そのスナップショットを再取得で上書きしない。
期限到来の取得がなければ従来の最古スナップショットを25件ずつ保存する。
既存lease・成功後24時間/失敗後1時間・取得元/8検索語/2MB/5000件上限を維持。
取得失敗時に同じ周期で追加保存へ切り替えず、旧データとカーソルを保持する。
失敗数や再試行期限の手動書換え、DBスキーマ/認証/Cron/定期タスク3件の変更なし。

追加2 JavaScriptケースで取得の滞留と失敗時の上限/保存保持を検証。
既存の保存/監視fixtureはSQLの役割ごとに行を返すよう修正し、未保存スナップショットを
取得候補へ返す不正なmockをやめた。別のPython/SQLiteテストは実際の取得SQLを実行し、
未保存・実行中lease・未来の取得予定を除外、完了済みと未取得だけを選ぶことを確認。

既存runJgrantsの返却値、監視、検証待ち表示、公開ロックを保持する。
