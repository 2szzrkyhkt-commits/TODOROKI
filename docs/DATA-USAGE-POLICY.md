## 1. 事実・数値と保護される表現を分ける

## 3. 由来・保存・表示

- 可能な限り、企業ID・対象期・連結/単体・単位・取得元・原資料の書類名/書類ID/ページまたはタグ・取得日時/更新日時・訂正元と訂正履歴・確認状態を元資料に結びつけて保持する。判明しない値は未確認とし、架空の値やゼロに置き換えない。
- 「原数値」「TODOROKI独自計算」「推計値」を分け、計算値・推計値には式・仮定・対象時点を示す。既存取得データの確認不足は公開保留で扱い、原データを無条件に削除しない。
- EDINETを基に加工した表示例：『出典：金融庁EDINET「有価証券報告書」（書類名・対象期・識別子）、PDL1.0。EDINET公表資料を基にTODOROKIが加工・計算。』法定提出日、対象期末日、書類に明記された決算発表日は別の項目にし、相互に流用しない。
- 本番からは内部の取得URL・資料キャッシュ・秘密情報を配信しない。監査用の証跡は承認された範囲でアクセスを制御し、既存DBを移行する前にバックアップする。

## 4. ソース追加・更新時の必須確認

1. 台帳に提供元・取得経路・公式条件URL・確認日・利用目的を記録し、著作権、アクセス、自動取得、保存・再配信、公開リンクを独立して評価する。不明な取得経路の既定値は停止。
2. 公式API・認証、アクセス制限、間隔を遵守し、重複取得を避ける。403/429や制限は回避せず、該当経路だけ止めて既存の正常な処理を維持する。
3. 規約や取得形式の変更は再審査し、根拠、可否、例外許諾の範囲と期限を残す。例外は別途承認。データを出典名だけ付け替えて引き継がない。
4. マージ前に由来、出典URL、条件と加工表示、禁止URL、レコード重複・誤計算、既存機能をテストする。本番では画面とデータ出力を両方確認し、未確認範囲を[既存ToDo台帳](TODOROKI-TODO.md)に記録する。CIの成功は規約審査や全件監査の代わりではない。

## 5. 取得済みデータを共通資産として使う

- 新規取得・制作前に、同じ目的で使える既存データ、抽出結果、計算結果、記事・教材・コードを確認する。正式な配信経路から取得した正常なデータは、適用法令・契約が許す保存期間、利用目的、公開・再配布の範囲内で永続保存・内部再利用する。許諾、鮮度、対象時点、改訂状態、権限は引き継ぎ、未確認の利用・公開は保留する。保持期限・削除義務を優先する。データの共通化はアクセス権を広げる理由にならない。
- 既存の台帳・ストレージを優先し、提供元・固有ID・バージョン・形式を一意キーとして使う。既存の正常データは消さず照合する。同一内容をハッシュで識別しても、異なる版・訂正・取下げ・出典・権利の記録を潰さない。旧版の保存は許容条件に従い、公開値は有効な版を用いる。
- 台帳には必要に応じて分類・資料名・内部取得URL、取得・公表・適用・更新・再確認日時、形式・容量・ハッシュ・保存先、保存・検証・抽出・反映状態、利用範囲・根拠条件と確認日、訂正・取下げ・廃止、エラーと再取得理由を持たせる。秘密はログに残さない。
- 本体取得前に台帳を照合し、全Worker・予約実行をまたぐ排他制御の内側で再確認する。正常保存済みなら本体や有効な計算を繰り返さない。未保存分だけ優先度付き待機列に入れ、検証・永続保存成功後に下流へ引き渡す。再取得は、更新・別版・訂正、破損・消失・保存失敗、必要形式の欠落、規約上の要求など根拠がある場合に限り、理由を記録する。
- 日付別一覧・検索結果と処理済み範囲・最終成功地点を保存し、新規・訂正・期限切れ・未収集を差分取得する。提供元が認める場合は ETag・Last-Modified と条件付きリクエストを使い、遅延・訂正・取下げだけ必要な範囲を再照合する。

## 6. 提供元別の取得制御と復旧

- 提供元単位で入口、待機列、排他、最短間隔、同時接続、時間・日次・API・クラウド上限を管理する。提供元ごとの正式な仕様・利用条件を優先し、EDINET向け暫定設定を他の提供元へ流用しない。各システムから同じ情報を別々に取得する経路は、同等のデータと権限を確認してから統合する。
- 403/429時は対象の提供元への不要なアクセスを止め、発生時刻・経路・応答の分類・直前の負荷・再開条件を残す。公式の Retry-After や再開条件を優先する。認証不備・明示的拒否、または拒否理由が判明していない場合、時間だけを理由に自動再試行しない。アドレス・プロキシ・キー・アカウント切替、連続再試行その他の回避は禁止。
- 取得、保存、検証、抽出、分類・計算、欠損補完、登録、反映、公開確認を分離する。外部停止時も保存済みの正常な資料で下流を進める。処理地点と次回可能時刻を永続化し、再起動後に重複せず安全に再開する。
- 優先は保存済み未処理、抽出済み未反映、保存資料による欠損補完、既存誤りの修正、新規・未収集、過去データ。緊急の訂正・制度変更は例外。初期・固定費は原則0円。既存の予約実行、ストレージ、接続、データを活用し、料金・権限・公開範囲を無断変更しない。
