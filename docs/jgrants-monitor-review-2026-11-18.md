# T45 Jグランツ収集の監視欠落を補完

既存の支援監視はsources/programs/revisionsのみを対象としており、別作業で追加された
jgrants_jobsの8検索語は含まれていなかった。11/18に各22回の失敗を手動SELECTで発見したため、
同じ状態を既存の監視記録で把握できるようにする。T45全体の通知連携完成とは区別する。

収集の取得/保存処理が終わってから、既存jgrants_jobsのメタデータだけを読み取る。
未取得、取得失敗後の再試行待ち、保存途中、空の取得結果、保存済み、48時間超の更新停止、
明示停止、未確認を区別する。候補の保存途中を全件保存済みとせず、空の一覧や取得失敗から
制度終了・対象制度なしを推定しない。過去の失敗を実行中の障害と断定しない。

失敗3回以上、48時間超の保存/更新遅延、欠落/不正なメタデータはattentionとする。
これは保存された状態の要確認フラグであり、外部通知や通知の配達成功ではない。
未来時刻・存在しない日付・不正カウンター・クリアされていないエラーは正常へ補完しない。
キーワードは既存8語のみ、取得行は最大9行で、追加/重複/未知のジョブを黙って無視しない。

既存support_monitor_latest/historyへjgrants:キー8件を追加する。正常な既存データや
カタログ/制度/受給条件/金額/ジョブのカーソル・次回時刻は変更しない。新規テーブル・Cron・
定期タスク・接続権限・公開API・外部通信/通知は追加しない。生の上流エラー/レスポンス本文は
監視記録へ入れず、状態と数値/時刻だけを保存する。

状態変更時だけの履歴追加と、古い観測での巻戻し防止は既存のトランザクション処理を共用。
DBが失敗を返した場合も成功扱いしない。監視の失敗は固定コードのmonitor.status=failedとして
収集結果へ付ける。収集の例外を監視の成功で隠さず、監視を試みてから元の例外を伝える。

追加5回帰ケースと既存6で11ケース、既存監視59/条件92/照合1079/金額598/自治体93検証成功。
本番では既存周期が8キーを保存し、保存途中の実カーソルと未処理7語の旧失敗を区別して
記録することをD1で照合する。T45全体/独立watchdog/外部通知到達、T29の全国網羅・公開は未完了。
