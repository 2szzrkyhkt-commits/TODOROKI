# T20 国税庁の取得順と文字コードの本番照合

前回の初回索引収集で候補823・保存2・残り821。FIFOでは先に発見したTax Answerが
通達より前に並び、一周期2件のままだと通達側の先頭に進むまで約8日かかる。
元のキュー・失敗の待機期限・原本・メタデータを維持して、両取得元を交互に選ぶ。
片側の取得対象がない/待機中のときは、他方へ残り枠を渡す。要求数は一周期2資料のまま。

保存結果の各2件について、URL・取得元区分・宣言文字コード・タイトル・原本の
サイズ/SHA256・読戻し結果をstatus.nta.verifiedへ残す。旧last_verifiedも保持。
タイトルは表示用に300文字までで、原本や保存メタデータの本文を切り詰めない。
未知の文字コード、不正バイト、取得失敗を正常へ補完しない。

Shift_JISについて、CloudflareのEncodingページの概要だけで未対応と判断しない。
公式履歴の2022-02-25項目はWHATWGの全エンコーディング対応を明示する。
https://developers.cloudflare.com/workers/platform/changelog/historical-changelog/
実資料 https://www.nta.go.jp/law/tsutatsu/kihon/shotoku/01.htm はShift_JIS宣言を確認。
追加デコーダー/辞書/Node互換フラグ/外部ライブラリは導入しない。

旧schema=1のFIFOキューで両元を2件以内に処理すること、将来の再試行期限を守ること、
取得順の永続化・再開、Shift_JISのタイトルと保存証跡を新規3ケースで検証。
既存13と合わせて16隔離ケース成功。tax配下の変更も既存PR CIへ含めるパスを追加し、
ジョブ・Cron・権限・通知先を増やさない。

本番の既存周期が保存したShift_JIS実資料の文字コード/タイトル/原本ハッシュを
独立取得と照合してから正本へ記録する。元の全対象収集は依然未完了。
