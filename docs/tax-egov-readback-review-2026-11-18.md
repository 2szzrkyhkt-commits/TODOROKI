# T20 e-Gov原本の読戻しと部分保存の再開

旧実装はrevisionメタデータがあればrawがなくてもskippedとしてキューから外す。
新規原本・revision/lawメタデータのputも読戻しなしで成功に数えていた。
隔離KVで原本なしのメタデータを用意すると、旧実装では期待する失敗が起きず、
新規回帰テストが失敗することを確認した。

新規原本はサイズ・XMLマーカー・SHA256を保存後に読戻し照合する。
revision/lawメタデータはJSON文字列の全文一致を確認してから成功に数える。
保存済みrevisionも法令ID・版ID・サイズ・ハッシュ・XMLを確認する。
原本欠落/破損は失敗して元キューへ残し、正常スキップや自動削除にしない。
revision保存後に索引保存が失敗した場合、次の周期で原本を検証したうえで
欠落した索引だけ復元する。異なる版を指す索引は上書きしない。
修復を新規取得数へ足さず、verified.index_repairedを別途記録する。
従来のtotal_savedは操作カウンターであり、全原本検証数の証明には使わない。

既存collectTaxの最大3件/周期、NTAの最大2件/周期、Cron、認証、binding、
履歴機能を維持。公開statusに本文/秘密値は追加せず、当周期最大3件の
法令ID/版ID/サイズ/ハッシュ/読戻し/索引修復だけ記録する。
直接KV読取は既存state/statusの限定のまま。

7隔離回帰ケース：保存済み原本欠落、新規保存、原本読戻し破損、
版メタデータ読戻し破損、索引書込失敗後の再開、異なる版の索引保持、
保存済み原本破損。実リクエスト/本番書込なし。
全件走査/全対象の照合完了ではなく、T20のチェックは増やさない。
実配備と既存周期の確認結果はTODO正本へ別途記録する。
